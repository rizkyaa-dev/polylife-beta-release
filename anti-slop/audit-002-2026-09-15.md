# Audit Percabangan Chat dan Transparansi Proses AI 002

Tanggal: 15 September 2026

Ruang lingkup: edit pesan tanpa kehilangan konteks, navigasi versi percakapan, konteks untuk percakapan panjang, serta tampilan proses AI yang membedakan reasoning dan tool call.

Arahan yang sudah tersedia: interaksi boleh mengambil referensi dari produk AI modern, tetapi visual, bahasa, dan tingkat kepadatan tetap mengikuti PolyLife.

## Pendekatan arsitektur

- Edit diperlakukan sebagai **fork immutable**. Isi pesan lama dan kelanjutannya tidak diubah atau dihapus; revisi membuat cabang baru dari parent pesan yang sama.
- Satu sesi memiliki cabang aktif. Setiap cabang menunjuk head terakhir, sedangkan setiap pesan menunjuk parent-nya. Kelompok revisi dipakai untuk navigasi `1 / 2`, `2 / 2`, dan seterusnya.
- Seluruh transcript dipertahankan di database. `ConversationContextAssembler` menyusun konteks cabang aktif sesuai anggaran token provider dengan checkpoint ringkasan, fakta penting, dan recent turns. Ini menjaga konteks praktis pada chat panjang tanpa mengklaim input model tidak terbatas.
- Satu generasi dicatat sebagai run dengan step terurut. Reasoning publik berupa ringkasan proses yang aman; tool activity memakai step terpisah dengan label, status, dan durasi. Chain-of-thought mentah tetap terenkripsi dan server-only.

## Temuan

### 1. HIGH - Edit pesan belum memiliki model data yang tidak destruktif (R-26, C-4)

- Lokasi: `database/migrations/2026_09_15_000002_create_ai_chat_tables.php:20-30`, `app/Models/AiChatMessage.php:13-28`.
- Pemicu: pengguna mengedit pesan lama setelah percakapan telah memiliki banyak balasan lanjutan.
- Kondisi saat ini: pesan hanya memiliki `session_id`, role, content, dan metadata respons; tidak ada parent, cabang, kelompok revisi, atau head aktif.
- Dampak: implementasi dengan `UPDATE content` akan membuat balasan lama seolah-olah menjawab prompt baru dan merusak integritas konteks. Menghapus semua pesan setelah titik edit juga menghilangkan riwayat pengguna.
- Perbaikan terarah: tambahkan model percabangan additive: `ai_chat_branches` (session, fork point, head), `parent_message_id`, `branch_id`, dan `revision_group_id` pada pesan, serta `active_branch_id` pada sesi. Backfill percakapan lama menjadi satu cabang linear. Pesan lama selalu immutable setelah completed.

### 2. HIGH - Belum ada kontrak edit, pindah versi, dan pengendalian race (R-26, BE-06, BE-12)

- Lokasi: `routes/web.php:119-126`, `app/Http/Controllers/Ai/AiChatController.php:24-48`, `resources/js/ai/workspace.js:56-98`.
- Pemicu: pengguna mengedit pesan, berpindah versi, atau mengirim pesan baru ketika generasi lain masih berjalan.
- Kondisi saat ini: hanya tersedia endpoint kirim pesan, rename/delete sesi, dan konfirmasi proposal. State `busy` hanya berada di tab browser dan tidak melindungi dua tab atau request bersamaan.
- Dampak: dua generasi dapat berebut cabang aktif, menghasilkan head yang salah atau balasan yang terpasang pada parent yang keliru.
- Perbaikan terarah: sediakan endpoint khusus `edit message` dan `activate branch`; gunakan application service tunggal untuk fork/switch. Awali run dengan transaction dan lock sesi, simpan revision/generation token, lakukan panggilan LLM di luar transaction, lalu commit hasil hanya jika token masih cocok. Hasil request yang kalah tetap dapat dicatat sebagai cabang nonaktif, bukan menimpa cabang aktif.

### 3. HIGH - Konteks model saat ini hanya membawa 10 pesan terakhir (R-27, C-4)

- Lokasi: `app/Services/Ai/AiAgentOrchestrator.php:259-278`.
- Pemicu: percakapan melewati lima pasang pesan atau pengguna mengedit pesan yang posisinya jauh di belakang.
- Kondisi saat ini: `loadSessionHistory()` mengambil tepat 10 pesan completed terakhir.
- Dampak: model kehilangan keputusan, koreksi, dan fakta lama. Edit berbasis cabang saja belum memenuhi permintaan konteks mendalam apabila perakit konteks tetap menggunakan limit ini.
- Perbaikan terarah: ekstrak `ConversationContextAssembler`. Ia harus membangun ancestry cabang aktif, menghitung anggaran token, mempertahankan recent raw turns, tool result yang masih relevan, dan checkpoint summary yang versioned per branch. Invalidasi checkpoint hanya mulai dari titik fork, sehingga bagian sebelum fork dapat digunakan ulang.
- Batas produk: seluruh riwayat dapat dipertahankan tanpa batas praktis di database, tetapi tidak mungkin menjamin seluruh teks mentah selalu masuk ke satu request karena context window provider terbatas. UI dan dokumentasi tidak boleh menjanjikan sebaliknya. DeepSeek juga menyatakan API chat bersifat stateless dan aplikasi harus mengirim konteks percakapan pada setiap request: https://api-docs.deepseek.com/guides/multi_round_chat/

### 4. HIGH - Workspace memotong tampilan menjadi 100 pesan tanpa pagination (R-27, C-4)

- Lokasi: `app/Http/Controllers/Ai/AiWorkspaceController.php:46-57`, `tests/Feature/Ai/AiWorkspaceViewTest.php:55-73`.
- Pemicu: pengguna membuka chat panjang atau berpindah ke versi yang fork point-nya berada sebelum 100 pesan terakhir.
- Kondisi saat ini: view hanya menerima 100 pesan terbaru dan test mengunci perilaku tersebut.
- Dampak: ancestry yang masih penting dapat hilang dari tampilan; navigator versi lama tidak punya anchor yang dapat dirender.
- Perbaikan terarah: muat tail cabang aktif secara cursor-based dan tambahkan “Muat percakapan sebelumnya”. Response branch harus membawa cursor, revision metadata, dan stable message ID. Jangan mengirim semua pesan sekaligus ke Blade.

### 5. HIGH - Aktivitas agentic tidak dipersistenkan sebagai timeline (R-26, C-4)

- Lokasi: `app/Services/Ai/AiAgentOrchestrator.php:90-150`, `app/Services/Ai/AiAgentOrchestrator.php:169-183`, `resources/views/ai/partials/message.blade.php:11-17`.
- Pemicu: model melakukan satu atau lebih tool call sebelum memberi jawaban.
- Kondisi saat ini: assistant/tool messages hanya hidup di array selama loop. Setelah selesai, database hanya menyimpan jawaban akhir, reasoning terakhir, dan proposal mutasi; tool baca dan reasoning antar-round hilang.
- Dampak: UI tidak dapat merekonstruksi urutan seperti “memahami permintaan → membaca jadwal → menyusun jawaban”, membedakan kegagalan tool, atau menampilkan durasi dengan jujur.
- Perbaikan terarah: tambahkan `ai_chat_runs` dan `ai_chat_run_steps`. Step minimal memiliki `sequence`, `kind` (`reasoning_summary|tool_call`), `status`, `label`, `duration_ms`, public metadata yang sudah direduksi, dan private payload terenkripsi bila benar-benar diperlukan. Persist setiap step secara append-only dan kaitkan run ke user message serta assistant message final.

### 6. HIGH - Menampilkan chain-of-thought mentah memperluas kebocoran data (SEC-04, R-38)

- Lokasi: `app/Models/AiChatMessage.php:24-28`, `tests/Feature/Ai/AiAgentTest.php:734-779`, `app/Services/Ai/Providers/OpenAiLlmClient.php:89-103`.
- Pemicu: UI membaca `reasoning_content` langsung untuk membuat panel “See thinking”.
- Kondisi saat ini: reasoning disimpan terenkripsi dan test secara eksplisit memperlakukannya sebagai internal yang tidak ditampilkan.
- Dampak: chain-of-thought mentah dapat membawa fragmen instruksi sistem, data pribadi hasil tool, asumsi yang dibatalkan, atau detail provider yang tidak cocok menjadi output produk.
- Perbaikan terarah: jangan kirim `reasoning_content` mentah ke browser. Tampilkan panel bernama **“Proses AI · 4 dtk”** yang berisi ringkasan tahap publik dan step tool terstruktur. Tool arguments/result ditampilkan melalui allowlist/redaction dan ringkasan domain, bukan dump JSON. Reasoning mentah tetap dipakai hanya untuk round-trip provider. DeepSeek memang mengembalikan `reasoning_content`, tetapi dukungan API tersebut bukan jaminan bahwa isinya aman dijadikan UI: https://api-docs.deepseek.com/guides/reasoning_model

### 7. HIGH - Endpoint message-level memerlukan authorization berantai (SEC-01, SEC-05)

- Lokasi: pola ownership yang sudah benar ada pada `app/Http/Controllers/Ai/AiChatSessionController.php:49-52` dan `app/Http/Controllers/Ai/AiChatController.php:26-33`.
- Pemicu: pengguna mengirim message ID, branch ID, atau cursor milik akun lain.
- Kondisi saat ini: belum ada endpoint message/branch sehingga belum ada policy untuk resource tersebut.
- Dampak: validasi `exists` global atau route-model binding biasa dapat membuka metadata, isi cabang, maupun tool trace lintas pengguna.
- Perbaikan terarah: semua lookup harus dimulai dari relasi sesi milik authenticated user, kemudian memastikan message dan branch berada pada sesi yang sama. Balas `404` secara konsisten untuk resource asing. Tambahkan negative tests untuk edit, switch, pagination, run steps, dan proposal lintas akun.

### 8. MEDIUM - Message component belum menyediakan state edit dan version navigation (R-32, R-31, R-27)

- Lokasi: `resources/views/ai/partials/message.blade.php:1-18`, `resources/css/ai-workspace.css:135-159`.
- Pemicu: hover/focus pada pesan pengguna, edit inline, simpan/batal, berpindah `1 / 2`, serta kegagalan regenerasi.
- Kondisi saat ini: bubble hanya merender teks. Tidak ada action bar, form edit, version control, status, atau recovery state.
- Dampak: menambahkan ikon hover saja akan tidak dapat ditemukan pengguna keyboard/touch dan tidak menjelaskan apakah riwayat lama masih tersedia.
- Perbaikan terarah: tampilkan action row saat `:hover` **atau** `:focus-within`; pada touch, action tetap dapat dibuka melalui tombol berlabel. Edit berlangsung inline dengan Save/Cancel, focus dipindahkan ke textarea, Escape membatalkan, dan error mempertahankan draft. Navigator versi memakai tombol panah berlabel dan counter teks. Setelah Save, cabang lama tetap bisa dipilih; jangan replay otomatis pesan-pesan setelah titik edit ke cabang baru.

### 9. MEDIUM - Reasoning dan tool call perlu hierarki semantik, bukan daftar dekoratif (R-04, R-20, R-21)

- Lokasi target: area sebelum jawaban assistant pada `resources/views/ai/partials/message.blade.php`.
- Pemicu: satu jawaban memiliki beberapa tahap reasoning publik dan beberapa tool call.
- Kondisi saat ini: proposal aksi langsung muncul setelah jawaban; belum ada progressive disclosure untuk proses.
- Dampak: semua tahap berpotensi terlihat sama penting atau membuat chat terlalu padat.
- Perbaikan terarah: gunakan satu native disclosure per jawaban: header `Proses AI · 4 dtk`, default collapsed setelah selesai dan terbuka selama processing. Reasoning memakai marker garis/titik netral; tool memakai ikon fungsional dan verba domain seperti `Membaca jadwal`, `Memeriksa to-do`, atau `Menyiapkan perubahan`. Status sukses/gagal tidak boleh dibedakan hanya dengan warna. Batasi animasi pada chevron dan loading indicator, serta hormati reduced motion.

### 10. MEDIUM - Kontrak respons kirim pesan belum membawa identitas dan metadata baru (R-26, C-2)

- Lokasi: `app/Http/Controllers/Ai/AiChatController.php:42-48`, `resources/js/ai/workspace.js:42-53` dan `73-82`.
- Pemicu: client perlu memasang edit/version controls dan timeline pada pesan yang baru selesai tanpa reload.
- Kondisi saat ini: respons hanya membawa session ID, reply, HTML, dan proposals; DOM yang ditambahkan tidak memiliki message ID, branch ID, revision index, run duration, atau steps.
- Dampak: UI tidak dapat mengedit pesan yang baru dikirim, berpindah versi, atau menampilkan proses secara konsisten sampai halaman di-refresh.
- Perbaikan terarah: gunakan response resource/versioned DTO yang mengembalikan user message, assistant message, active branch, revision metadata, dan public run steps. Render server-load dan append client dari shape yang sama agar state tidak bercabang antara Blade dan JavaScript.

## Hal yang sudah baik

- Ownership sesi telah dimulai dari relasi user dan dapat dijadikan pola untuk branch/message authorization.
- Reasoning provider sudah dienkripsi at rest dan dibawa kembali pada tool loop.
- Markdown jawaban disanitasi dan memiliki regression test XSS.
- Composer telah memiliki busy, loading, retry draft, dan error state yang dapat diperluas ke edit flow.
- Tool mutasi tetap berupa proposal yang memerlukan konfirmasi; branching tidak perlu mengubah batas keamanan ini.

## Paket persetujuan yang disarankan

- Fondasi integritas percakapan: 1, 2, 3, dan 4.
- Transparansi agentic yang aman: 5, 6, dan 9.
- Endpoint dan UI lengkap: 7, 8, dan 10.
- Rekomendasi: setujui 1-10 sebagai satu perubahan end-to-end. Implementasi bertahap tetap diperlukan: migration/backfill → branch/context services → run steps → endpoint/resources → UI → tests.
- Keputusan produk yang disarankan: revisi membuat cabang baru dan menghasilkan jawaban baru mulai dari pesan yang diedit; pesan-pesan lama setelah titik edit tidak diputar ulang otomatis, tetapi tetap utuh pada versi sebelumnya.
- Batas keamanan yang disarankan: “See thinking” menampilkan ringkasan proses dan aktivitas tool yang telah disanitasi, **bukan chain-of-thought mentah**.
