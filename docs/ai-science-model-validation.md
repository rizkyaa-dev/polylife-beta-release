# Scientific model preparation and evidence

This is the first domain-verification layer, not a universal physics verifier.
It separates source declarations, deterministic model preparation, numerical
execution and confidence reporting. The first allowlisted strategy is `rc_linear`.
Other scientific tasks retain the existing explicitly unverified generic path.

## Runtime and trust boundaries

```text
Backend-retained user wording
  + untrusted science-agent domain declaration
        -> allowlisted model strategy
        -> bounded source/topology checks and deterministic equations
        -> existing solver preflight
        -> numerical server execution OR browser Worker candidate
        -> server rebuild + numerical replay
        -> granular evidence and limited numerical result
```

`ScienceModelRegistry` dispatches only compiled-in `ScienceModelValidator`
implementations. Model data cannot name a PHP class, load a plugin, execute code,
or elevate its verification status. `PreparedScienceModel` is an immutable
server-created value object. The validator replaces proposed solver equations;
it does not endorse an LLM AST because it happens to have valid dimensions.

Preparation runs before suspension and again on deterministic completion. Resume
does not call the planner again. Existing cancellation/deadline guards and the
one-repair planning bound apply; there is no unbounded agent loop. Malformed
supported-domain declarations fail validation without numerical execution.
Unknown domains must omit `domain_model` to use generic inputs, with no domain
evidence; they are never dynamically loaded or silently accepted as checked.

The browser receives numerical `solver`/`inputs`, not the raw source, domain
declaration or model-verification authority. Client results and cached values are
only candidates. Server replay reconstructs equations and evidence from the
private plan; it does not adopt candidate verification labels. The full retained
source stays in encrypted private payloads and is removed from model-facing tool
history. Bounded evidence quotes remain available for transparent explanation.

Scientific contracts forwarded to coding undergo model preparation again.
Canonical comparison checks that regenerated numeric inputs still match the
reference; changed equations require recomputation. Stored evidence is not
trusted as a fresh assessment. The canonical representation preserves list/state
order, sorts object keys, distinguishes numeric strings from numbers, bounds
depth/node count, and tolerates JSON's integer/float roundtrip for equal numbers.

## Contract and supported RC scope

See `tests/Fixtures/science-rc-domain.json` for a complete executable example.
The optional `domain_model` uses `version: model-v1`, `domain: rc_linear` and:

- Nodes: exactly one ground, up to four dynamic voltage nodes with initial
  quantities, and constant ideal fixed-voltage nodes; at most nine nodes total.
- Components: unique IDs, two distinct existing endpoints, and a source-unit
  quantity for each ideal resistor/capacitor; at most sixteen components.
- Each component requires **both** its own top-level connection `quote` and
  `value.quote`. Missing/unknown fields are rejected, not silently inferred.
- Positive R/C, exactly one grounded capacitor for each dynamic node, and a
  resistor incident on every dynamic node. Coupling/floating/parallel capacitors,
  inductors, nonlinear/switching devices and current sources are not supported.
- Source-quoted start/end times, a finite increasing interval, a local absolute
  voltage tolerance in `1e-8..1e-2`, and one to four unique selected dynamic-node
  voltage outputs. State order follows the dynamic nodes in the declared list.

Ready RC proposals select `ode_ivp` and omit `inputs`. The server constructs:

```text
C_i * dV_i/dt = sum over incident resistors ((V_neighbor - V_i) / R)
```

Resistor endpoint orientation cannot change the resulting physics. Balanced
binary summation keeps generated AST depth bounded. Source-unit conversions use
the same trusted unit registry as the numerical kernel. Conversion provenance is
generated by walking the final AST, including every repeated constant; internal
source annotations are removed before inputs reach the kernel or Worker.
Exceeding the kernel's 32-conversion limit fails closed even within the broader
node/component limits; reduce the network or use another explicitly unverified
supported formulation. No solver-resource limit is relaxed.

## Evidence means specific checks, not physical truth

The backend produces `model_evidence`, never trusts a provider/client claim, and
keeps `model_verification: unverified`. A successful domain preparation reports
`declared_structure_checked` with individually scoped checks:

| Check | Meaning |
|---|---|
| Source quantity binding | Number/unit occurrences match bounded exact source quotes, except explicitly listed interpretations |
| Source quote presence | Declared quantities and connections have exact quotes in retained text |
| Declared topology | IDs/endpoints, component positivity and grounded capacitances are valid within RC scope |
| KCL construction | Equations are built deterministically from that declared topology |
| Declared initial conditions | Each dynamic node has a normalized initial voltage |
| Text interpretation/completeness | **Unverified**: omitted facts, quote context and intended connectivity are not proven |
| Physical idealizations | **Assumed**: ideal constant lumped R/C and constant ideal voltage sources |
| Numerical applicability | **Unverified**: the model builder does not certify nonstiffness or global error |

`SourceQuantityBinder` is deliberately narrow. It checks finite source values,
supported unit spellings, exact quotes and literal number/unit pairs. It does
not solve natural-language interpretation. Compound units, fractions, arithmetic
expressions and unsupported notation must not be misread as scalar quantities.
Unicode negative voltages preserve their sign. Decimal-comma/point and scientific
notation are supported literal spellings, but locale and contextual semantics
remain outside the claim. Quotes may contain more than one quantity; occurrence
does not prove which physical component the user intended.

Zero initial voltage from an uncharged-capacitor phrase and zero time origin from
an initial-instant phrase are narrowly supported interpretations. They are listed
explicitly as `uncharged_initial_interpretation` / `zero_time_origin_assumed`,
not promoted to source-semantic proof. Even literal scalar matches cannot prove
the declaration is complete or the user's real component values are correct.
For high-assurance usage, obtain explicit user-confirmed structured facts rather
than relying on these interpretations. Cross-domain cases receive no fabricated
domain evidence. Local numerical estimates remain local estimates.

## Extending safely

1. Add one cohesive `ScienceModelValidator` strategy in `Science/Models`, with a
   unique domain, versioned specification, strict bounded schema and explicit
   unsupported scope. Register it through trusted constructor wiring only.
2. Return deterministic `PreparedScienceModel` inputs, state order and scoped
   evidence. Reuse the unit registry and existing AST/dimension/output contracts;
   do not implement a parallel numerical engine or insert candidate answers.
3. Keep factual interpretation, idealizations and numerical guarantees separate.
   No strategy may upgrade the registry's overall physical-truth status.
4. Add mutation tests, independent analytical references, symmetry/orientation
   properties and relevant conservation/passivity checks. Test malformed input,
   forged metadata, JSON persistence, callback replay and coding-contract reuse.
5. Version changed contracts/strategies and retain compatibility deliberately.
   Evidence fingerprints bind model-registry version, strategy version, canonical
   declaration, source digest and generated inputs. Current code rechecks rather
   than trusting a model-verdict cache.

The numerical kernel version remains `science-kernel-1.8`: these changes introduce
model-v1 / science-models-1 / rc-linear-1, not a new numerical method. Numerical
browser caching remains owner- and kernel/input-scoped; physical evidence is not
cached as browser authority. No new tables, global locks, queues or inference
reviewers are added. The domain preparation layer is stateless, so adding domains
does not create a central mutable coordinator or additional per-user state.

## Validation and deployment

The tests cover wrong-sign/candidate AST replacement, KCL/passivity at independent
state probes, the analytic RC transient, resistor orientation invariance, explicit
state ordering, malformed/unsupported models, quote/value/unit mismatch,
unsupported source notation, forged client evidence, private-source projection,
JSON persistence and stale coding references. A Node test executes the actual
server-generated RC inputs through the existing JS kernel and checks PHP parity;
this is not an actual browser/UI run.

Manual commands (the provider probe is paid and stores private evidence):

```powershell
php artisan test --compact
node --test tests/Js/ai-science-kernel.test.js
php tests/Support/science-domain-reference.php --benchmark
php tests/Support/science-adversarial-probe.php rc
```

Publish all new PHP model strategies and restart long-running AI/queue workers
when deploying. No production service restart or migration is performed by this
implementation. Production concurrency, provider tail latency and browser/UI
validation remain separate deployment gates; a sub-millisecond preparation
benchmark is not evidence of thousands of concurrent users.
